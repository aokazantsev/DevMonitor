# DevMonitor — инструкции для Claude

Полное описание поведения, настроек и файлов — в `README.md`. Прочитать его целиком перед любой
правкой: он же карта «что где менять». Этот файл — только правила работы с проектом.

## Что это

Оверлей Windows (WinForms, .NET Framework 4.8): загрузка и температура CPU/GPU, ОЗУ, VRAM, память
Android Studio / Gradle / Kotlin, история по минутам, статистика, трей, настройки железа. Плюс
установщик и деинсталлятор. Аудитория — разработчики на Windows, железо любое из справочника.

## Сборка

- Только штатный `csc.exe` из `%WINDIR%\Microsoft.NET\Framework64\v4.0.30319` — SDK и NuGet не
  используются. Это **C# 5**: нет `$"..."`, `?.`, `nameof`, `=>`-членов, инициализаторов авто-свойств,
  `out var`.
- `build.cmd` — программа (`build.cmd nostart` — без запуска). `build-installer.cmd` — программа,
  `Uninstall.exe`, архив и установщик в `dist\DevMonitorSetup.exe`.
- Репозиторий и установленная копия (`C:\Program Files\DevMonitor`) — разные папки. Сборка трогает
  только свой `DevMonitor.exe`: занят — переименовывается в `DevMonitor.old.exe`. Установленный
  экземпляр сборка не закрывает; обновить его — установщиком.
- Запуск программы с правами — за пользователем (ярлык). Для проверки без прав — обвязка в папке
  scratchpad (см. ниже), не реальная установка.

## Проверка изменений

- История и настройки живут в `%LOCALAPPDATA%\DevMonitor`, а не рядом с exe. Обвязка для снимков
  не должна создавать `HistoryRecorder` и `OverlayForm`: они пишут в настоящую историю пользователя.
- Интерфейс проверять снимками: отдельная обвязка (свой `Main`), окно → `DrawToBitmap` или
  `CopyFromScreen` → PNG → посмотреть. Скриншоты README — `docs\*.png`, поменял интерфейс — переснять.
- Нагрузку мерить: CPU-время процесса за 60 с (цель — доли процента), private-память.
- Установщик по-настоящему не запускать (ставит драйвер, ярлык, реестр) — это делает пользователь.
  Окно установщика проверять обвязкой без запроса прав.

## Правила кода

- Комментариев в коде нет вообще, KDoc/XML-doc тоже; имена говорят сами.
- Один класс — один файл. `if/else` вместо `switch` на две ветки.
- Ресурсы экономить: никаких фоновых потоков и таймаутов чаще раза в секунду, опрос процессов —
  раз в 3 с, отрисовка — только при изменении.
- В справочник `hardware.csv` — только железо, которое реально читается (CPU — семейства
  LibreHardwareMonitor из `lib\`, GPU — только NVIDIA через NVML). Пороги — по правилам из шапки файла,
  значения — со страниц производителей.

## Грабли

- Heredoc в Bash-инструменте ест обратные слэши, `sed` превращает `\f` в form feed: правки со `\`
  делать python-скриптом из файла (`chr(92)`) или инструментом записи, результат сверять.
- `.cmd` должны быть в CRLF и чисто ASCII (кириллица с `chcp 65001` сбивает разбор строк); `find` в них —
  полным путём `%WINDIR%\System32\find.exe` (иначе Git-овый); соседние скрипты — `call "%~dp0build.cmd"`
  (в окружении Claude Code cmd не ищет в текущей папке).
- PowerShell-обёртка над `.cmd` со `start` висит до закрытия программы — собирать с `nostart`.
- `taskkill` из обычной консоли не убивает процесс, запущенный от администратора.
- В установщик попадает только перечисленное в `installer\payload.txt`.

## Общее с другими pet-проектами

Проект — один из трёх pet-проектов (ClaudeVpnGuard, DevMonitor, ClaudeGlow), они устроены одинаково:
похожий интерфейс, одинаковые установщик, деинсталлятор, порядок меню и код общих частей.

- **Общие файлы** — одинаковые во всех трёх, отличается только `namespace`:
  `installer\setup\{SetupForm, Installation, InstallTarget, Payload, SetupOption, SetupField,
  InstallRequest, SetupProgram, SetupLog}.cs`, `installer\common\{UninstallRegistration, RunningApp}.cs`,
  `installer\uninstall\UninstallProgram.cs`, `src\{AboutForm, CrashReportConsent, CrashUploader}.cs`.
  `build.cmd`, `build-installer.cmd`, `installer\make-payload.ps1` отличаются только переменными
  в начале. Поменял общий файл — та же правка в двух других проектах.
- **Своё у проекта:** `src\AppIdentity.cs` (имя, версия, ссылки, пути), `src\Autostart.cs` (задача
  Планировщика или ключ Run), `installer\setup\SetupProfile.cs` (тексты, поля, галочки, свои шаги),
  `installer\uninstall\UninstallProfile.cs`, `installer\payload.txt` (что ставится), `src\CrashReport.cs`
  (перехват падений: куда пишет текст ошибки — у каждого свой журнал).
- **Надёжность:**
  - журнал `log.txt` пишет запуск (версия, пользователь, Windows, настройки), шаги запуска и причину
    каждого отказа — по нему «не завелось» разбирается без догадок;
  - `Program.cs` перехватывает падения (`AppDomain.UnhandledException` с
    `[HandleProcessCorruptedStateExceptions]`, `Application.ThreadException`), `CrashReport` пишет
    стек в журнал и показывает окно; отчёт на `AppIdentity.SiteUrl + "crash-report"` — только по
    согласию из установщика (галочка по умолчанию выключена), один раз, без повторов;
  - опасные системные вызовы (COM брандмауэра, драйверы, нативные DLL) не должны молча убивать
    программу: отдельный процесс с таймаутом или перехват плюс метка «прошлый запуск умер здесь»;
  - сбои окружения программа по возможности лечит сама; проблема и починка видны на значке в трее
    (метки ошибки и починки), в подсказке, меню и журнале. Свои проблемы — только в трее и
    уведомлениях, не в основном результате программы.
- **Меню трея:** блок состояния; действия приложения; «Настройки…», «Журнал» (если есть),
  «Запускать при входе в Windows», «О приложении…»; «Выход».
- **Установщик:** права администратора, выбор папки (по умолчанию `C:\Program Files\<Имя>`), галочка
  автозапуска, сам останавливает запущенную копию, после установки запускает программу. Регистрация
  в «Приложениях» — в HKLM. Деинсталлятор сам закрывает программу и удаляет её данные.
- **Установка поверх любой прежней версии обязана работать** (правило с версии 1.9): установщик сам
  останавливает запущенную копию, заменяет файлы, пересоздаёт задачи Планировщика и записи реестра
  (`/F`, перезапись), настройки старых версий читаются — незнакомые ключи пропускаются, пропавшие берут
  значения по умолчанию, форматы данных остаются читаемыми или переводятся при запуске. Удалять старую
  версию перед установкой пользователь не должен никогда. Перед релизом — установка поверх предыдущего
  релиза и проверка журнала.
- **Любая правка доводится до конца:** версия в `AppIdentity.Version` и трёх `AssemblyInfo.cs`, запись
  в `CHANGELOG.md`, сборка `build-installer.cmd`, проверка Защитником, коммит и push, Release на
  GitHub с установщиком, при необходимости — README, скриншоты в `docs\` и страница на
  aokazantsev.ru/pets.
